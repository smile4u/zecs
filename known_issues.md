# Known Issues

Открытые ошибки, ограничения и технический долг, сверенные с текущим кодом.
Номера сохранены для существующих ссылок; закрытые пункты удалены.

## Черновая реализация: события

События (`src/zecs/events.h`, `src/zecs/view_events.h`, раздел Events API в `src/zecs/world.h`)
— черновик. Код не доведён и не проходил ревью; пользоваться им в рабочем коде пока не стоит.
К событиям относятся пункты 1, 6 и 21.

### 21. Добавление события инвалидирует `view_events`
- **Место:** `src/zecs/view_events.h` — `ViewEvents`, `ViewEventsIter`.
- View хранит итераторы `std::deque`. `event_push<T>` во время обхода событий того же типа
  (или между созданием view и вызовом `begin()`) делает их недействительными; то же делает `raw_gc`.
- Выведено из кода, под санитайзером не воспроизводилось.

## Ошибки

### 1. `World::event_push<T>(Args&&...)` не передаёт тик
- **Место:** `src/zecs/world.h` — `World::event_push`; `src/zecs/events.h` — `EventDeque::push`.
- Вызов `push(T(std::forward<Args>(args)...))` не передаёт обязательный второй аргумент `GTick`.
- **Проверено компиляцией:** создание события из нуля, одного и двух аргументов
  не компилируется. Передача готового события, например `world.event_push(Event{5})`, работает.

### 3. Реентерабельность сигналов добавления и удаления
- **Место:** `src/zecs/comp_pool.h` — `CompPool2::add`, `CompPool2::remove`.
- `on_removed.Emit` вызывается до уничтожения компонента и освобождения dense-слота.
  Повторное удаление того же компонента из обработчика может вызвать бесконечную
  рекурсию либо повторное уничтожение и повреждение структур пула.
- Если обработчик `on_added` удалит добавленный компонент, `add` вернёт указатель
  на объект, время жизни которого уже завершилось.

### 4. Повторный `comp_add` нарушает соответствие sparse/dense
- **Место:** `src/zecs/comp_pool_base.cpp` — `CompPool2Base::dense_add`.
- Отсутствие компонента проверяется только через `assert`. В Release повторное
  добавление перезаписывает sparse-индекс, но оставляет прежний компонент живым
  в другом dense-слоте: обход выдаёт сущность повторно, старый компонент недоступен через `get`.
- Предусловие «компонент ещё не добавлен» требует явного контракта либо проверки.

### 10. Счётчики компонентов и пулов не обновляются
- **Место:** `src/zecs/world.h` — `World::Counters`; `src/zecs/world.cpp`.
- Поддерживается только `entities`; поля `components` и `pools` всегда равны нулю.

### 12. Добавление сущностей инвалидирует `view_entities`
- **Место:** `src/zecs/view_entities.h` — `ViewEntitiesIter`.
- Итератор хранит обычные итераторы вектора `entities`. Добавление сущности
  с реаллокацией делает их висячими; сохранённый `end` инвалидируется и без реаллокации.

### 15. `TaskGraph::init` резервирует не тот список
- **Место:** `src/zecs/task.cpp` — `TaskGraph::init`.
- Перед заполнением `tasks_step_fixed` вызывается
  `tasks_step_normal.reserve(step_fixed_ids.size())` вместо `tasks_step_fixed.reserve(...)`.

## Ограничения и открытые вопросы API

### 5. Слоты сущностей не переиспользуются; у ID нет поколений
- **Место:** `src/zecs/world.cpp` — `World::entity_add`, `World::entity_remove`;
  `src/zecs/types.h` — `EntityBase`.
- `entity_free_index` не меняется после инициализации, ветка free-list не реализована.
  Размер `entities` растёт с общим числом созданных сущностей, включая удалённые.
- ID имеет 32 бита. При реализации переиспользования слотов потребуется защита
  от совпадения старого ID с новой сущностью, например счётчик поколений.

### 6. Автоматическая очистка событий отсутствует
- **Место:** `src/zecs/events.h` — `EventDeque::raw_gc`.
- Метод очистки есть, но движок его не вызывает. Без ручной очистки события
  накапливаются всё время жизни мира.

### 7. `comp_patch(Entity e, T* comp)` игнорирует указатель
- **Место:** `src/zecs/world.h` — соответствующая перегрузка `World::comp_patch`.
- Выполняет ту же работу, что перегрузка без указателя; назначение параметра `comp` не определено.

### 9. GUID типов непереносимы между сборками; коллизии не обнаруживаются
- **Место:** `src/zecs/guid_crc.h` — `func_CRC32`; `src/zecs/guid.cpp` — `uid_index_register`.
- CRC32 вычисляется из `__PRETTY_FUNCTION__` / `__FUNCSIG__`. Стабильность ID
  между компиляторами и их версиями не гарантируется; для сохранений и сетевого
  протокола с такими ID нужен отдельный стабильный формат.
- При коллизии реестр выдаст двум типам один индекс пула без проверки типа.

### 14. Патч обходящегося пула меняет порядок patch-view
- **Место:** `src/zecs/comp_pool_base.h` — `PatchIt`;
  `src/zecs/comp_pool_base.cpp` — `dense_patch`.
- Патч переносит узел в голову списка, поэтому ещё не посещённый узел, пропатченный
  во время прохода, в этом проходе пропускается (его увидит следующий проход).
  Компоненты, добавленные во время прохода, в него тоже не попадают.
- Повторных визитов и зацикливания нет: итератор помнит тик текущего узла и движется
  только к более старым. Ссылка на следующий узел сохраняется до выполнения тела цикла,
  поэтому патч или замена текущего компонента обходятся без поиска.
- Если тело цикла пропатчило следующий узел или переиспользовало его слот, позиция ищется
  от головы списка; цикл, делающий это на каждом шаге, работает за квадратичное время.
- Требование: каждый новый тик патча больше всех прежних (через `World` выполняется всегда).
- Удаление, замена (remove + add) и патч текущего и будущих компонентов поддерживаются
  и покрыты `tests/test_view_patched_mutation.cpp`.

### 16. Частота fixed-step по умолчанию требует уточнения
- **Место:** `src/zecs/task.h` — `TaskGraph::FIXED_TIME_DEFAULT`.
- Значение `0.27f` задаёт примерно 3.7 шага в секунду. Ожидаемая частота не описана.
  Аккумулятор суммирует `dt` между вызовами, поэтому лимит `step_dt_limit = 0.25f`
  не мешает выполнению fixed-step; само значение не является подтверждённой ошибкой.

### 20. Sparse-массивы растут до максимального ID и не сжимаются
- **Место:** `src/zecs/comp_pool_base.cpp` — `CompPool2Base::dense_add`.
- Каждый пул хранит sparse-массив до максимального ID сущности, когда-либо
  получившей его компонент. Расход памяти зависит от диапазона ID, а не только
  от числа живых компонентов, и увеличивается при большом количестве пулов.

### 21. Холодный последовательный обход на Apple Silicon стал медленнее
- **Место:** `src/zecs/comp_pool.h` — `CompPool2::get`.
- `get` считает адрес компонента из dense-индекса и не читает указатель из `comps[]`.
  На случайном доступе это быстрее на 56–72%, на тёплом обходе с чтением — на 22%.
- Процессоры Apple сами подгружают данные по указателям из прочитанной строки кэша,
  и прежний код получал эту предзагрузку даром. Без неё `zecs_bench`
  View_50K / 100 компонентов на M1 Max медленнее на 13–15%; остальные 11 строк быстрее.
- Предзагрузка внутри `get` возвращает около половины потери, но отнимает выигрыш
  на тёплых циклах. Подходящее место для неё — итератор view; не сделано.

## Технический долг

### 17. Неиспользуемый и отключённый код
- `globalTick` — `src/zecs/types.h`; `TransparentHasher`, `TransparentEqualTo` — `src/zecs/traits.h`.
- `world_unique_id_counter` — `src/zecs/world.cpp`.
- `DbgInfo` / `DbgPtr` не используются; `ZECS_DEBUG` определяется безусловно — `src/zecs/debug.h`.
- Отключённый через `#if 0` API `view_patched_group` — `src/zecs/world.h`.

### 18. Настройка CMake
- **Место:** `CMakeLists.txt`.
- В `target_include_directories` тестов переданы `${TST_SOURCES}` (файлы),
  а не `${TST_DIR}` (каталог).
- Нет правил установки, экспорта целей и package-config для подключения через `find_package`.

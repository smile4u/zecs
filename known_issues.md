# Known Issues

Отчёт о найденных багах и проблемах проекта. Сгруппировано по серьёзности.
Позиции с пометкой *checked* подтверждены компиляцией или демонстрацией.

## Критические (UB / некорректная работа)

### 1. `World::event_push<T>(Args&&...)` не компилируется — *checked*
- **Место:** `src/zecs/world.h:418`
- **Описание:** перегрузка вызывает `push(T(std::forward<Args>(args)...))` одним аргументом,
  а `EventDeque<T>::push` объявлен как `push(T&& event, GTick tick)` (`src/zecs/events.h:41`).
- **Проявление:** ошибка компиляции при инстанцировании `world.event_push<DamageEvent>(5)`.
  Латентный — ни один тест не использует эту перегрузку.
- **Примечание:** при одном аргументе перегрузка недостижима (выигрывает `event_push<T>(T&&)`),
  при двух и более — не компилируется. API событий фактически поддерживает только move-перегрузку.

### 2. `PatchIt` — UB при удалении текущего элемента во время обхода — *checked*
- **Место:** `src/zecs/comp_pool_base.h:103`, `src/zecs/comp_pool_base.cpp:79`
- **Описание:** `PatchIt::operator++` читает `links[head].next`, а `dense_rem` при удалении
  компонента перезаписывает эту ссылку указателем free-list. Итератор начинает идти по
  free-list.
- **Проявление:** демонстрация: `view_patched_comps` с удалением текущего элемента —
  `seen=1` вместо 1000; возможны мусорные сущности, ранний выход, бесконечный цикл.
- **Примечание:** фикс (кэширование преемника в итераторе) был реализован и откачен по
  решению владельца. Проблема актуальна.

### 3. Реентерабельность сигналов
- **Место:** `src/zecs/comp_pool.h:131` (remove), `src/zecs/comp_pool.h:103` (add)
- **Описание:** `on_removed.Emit` вызывается **до** `~T()` и `dense_rem`. Если обработчик
  повторно удалит тот же компонент — двойное уничтожение / двойной `dense_rem` на одном
  слоте → порча структур. `on_added.Emit` вызывается до возврата `T*`; обработчик,
  удаливший только что добавленный компонент, оставляет возвращённый указатель висячим.
- **Проявление:** требует обработчика с повторным `comp_remove` в том же колбэке.

### 4. `comp_add` на уже существующий компонент
- **Место:** `src/zecs/comp_pool_base.cpp:29` — `assert(sparse[si] == DIndex_NONE)`
- **Описание:** повторный `comp_add<T>(e, ...)` на сущности, уже владеющей `T`, в release
  без ассерта создаёт осиротевший dense-слот и теряет старый компонент (двойное
  уничтожение при деструкторе пула).
- **Проявление:** только при нарушении недокументированного предусловия.

## Данные / логика

### 5. Free-list сущностей не реализован
- **Место:** `src/zecs/world.cpp:27-30`
- **Описание:** `entity_free_index` нигде не присваивается, ветка под
  `assert(false); // TODO: implement`. Слоты сущностей не переиспользуются.
- **Следствия:**
  - вектор `entities` растёт без переиспользования слотов — память растёт с максимальным
    числом сущностей за всё время;
  - при будущей реализации free-list без generation-счётчика (TODO в `world.h:229`)
    возможен стейл-хэндл-алиасинг (повторное использование хэндла старым указателем).

### 6. `raw_gc` никогда не вызывается
- **Место:** `src/zecs/events.h:22,40`
- **Описание:** GC событийных дек существует, но нигде не вызывается — деки растут
  неограниченно всё время жизни мира.

### 7. `comp_patch(Entity e, T* comp)` игнорирует `comp`
- **Место:** `src/zecs/world.h:352-357`
- **Описание:** перегрузка с указателем на компонент не использует его (делает то же,
  что перегрузка без указателя). Вводит в заблуждение.

### 8. No-op патч потребляет тик
- **Место:** `src/zecs/world.h:244,348`
- **Описание:** `comp_patch` сущности, не владеющей компонентом, всё равно выполняет
  `tick++` (тик сжигается без изменения состояния).

### 9. GUID зависит от компилятора + коллизии
- **Место:** `src/zecs/guid_crc.h:52-62`
- **Описание:** `func_CRC32<T>()` хеширует `__PRETTY_FUNCTION__`/`__FUNCSIG__`, которые
  различаются у GCC/Clang/MSVC и между версиями компиляторов. Один и тот же тип получает
  разные `globalUid<T>`.
- **Следствия:** ломается любая сериализация/репликация/сейвфайлы между компиляторами.
  Плюс 32-битный CRC: коллизия двух типов молча сливает их в один пул через глобальный
  реестр индексов.

### 10. `counters.components` и `counters.pools` никогда не обновляются
- **Место:** `src/zecs/world.h:29-33`, `src/zecs/world.cpp`
- **Описание:** `Counters::entities` поддерживается, а `components`/`pools` всегда 0 —
  мёртвые поля.

### 11. `ViewCompGroupBase::init` — out-of-bounds при `pools_count == 0`
- **Место:** `src/zecs/view_comps_group.cpp:24`
- **Описание:** `pools_ptr[0]` при пустом массиве (runtime-перегрузка
  `view_comp_group(guids, 0)`).

## Висячие итераторы / UB при мутациях (не покрыто тестами)

### 12. `view_entities` + добавление сущности во время обхода
- **Место:** `src/zecs/view_entities.h:15`
- **Описание:** `ViewEntitiesIter` хранит итераторы во внутренний вектор `entities`;
  добавление сущности → реаллокация → висячие итераторы → UB.

### 13. Групповое вью + добавление нового типа пула во время обхода
- **Место:** `src/zecs/view_comps_group.h:45`, `src/zecs/world.cpp`
- **Описание:** `pools_ptr` указывает на `comp_pools_packed`, который реаллоцируется при
  создании нового пула (компонент нового типа) → висячий указатель → UB.

### 14. `PatchIt` + удаление «будущего» элемента / патч во время обхода — *checked*
- **Место:** `src/zecs/comp_pool_base.h:103`
- **Описание:** удаление следующего (не текущего) элемента во время обхода приводит к
  выдаче `Entity_INVALID` (мусор) — демонстрация: список `c → b → a`, удаление `b` при
  визите `c` даёт `e=-1`. `comp_patch` во время обхода переносит узлы в голову списка →
  повторные/пропущенные визиты.

## Мелочи / чистота

- **Описание:** `tasks_step_normal.reserve(step_fixed_ids.size())` вместо

- **Место:** `src/zecs/task.h:32`
- **Описание:** подозрительное значение фиксированного шага (вероятно, подразумевалось
  1/60 ≈ 0.0167). При dt ≤ 0.25 аккумулятор почти никогда не срабатывает.

### 18. CMake
- `file(GLOB_RECURSE ...)` для исходников библиотеки;
- нет `install` / экспорта / package-config — библиотеку нельзя потреблять через
  `find_package`;
- `target_include_directories(${PROJECT_NAME}_tests ... ${TST_SOURCES})` — переданы
  файлы исходников вместо `${TST_DIR}`.

### 19. `Entity` 32-битный без поколений
- Лимит ~4 млрд сущностей; риск стейл-хэндл-алиасинга при реализации free-list (см. #5).

### 20. Sparse-массивы O(max entity) на пул, не сжимаются
- **Место:** `src/zecs/comp_pool_base.cpp:28`
- **Описание:** sparse растёт до максимального индекса сущности, когда-либо получившей
  компонент в пуле, и никогда не уменьшается. При большом количестве сущностей и
  множестве пулов — значительная память.
